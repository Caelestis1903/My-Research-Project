# Stage F：基于 Phase 2B 文献分析的多方向系统性算法研究

## 一、任务背景与最终目标

我正在开展多域多任务推荐系统（MDMT）研究，主要基于 M3OE / Mixture-of-Experts 框架，目标是在 RecSys、SIGIR、WWW、KDD、AAAI 等推荐系统认可度较高的会议上形成具有竞争力的**新算法或新模型结构**，主要关注 AUC 改善。

此前已经完成：

- Phase 1：115 篇相关论文的文献整理与分析。
- Phase 2B：独立于历史实验，系统分析文献中的方法能力、限制、创新谱系与十个算法研究机会 AO-01～AO-10。
- S0–S8：围绕 M3OE、Sample/Equal objective、梯度与优化过程的历史实验。
- R0/R1/R2：选择 AO-04 中的静态非均匀他域专家融合进行正式实验。
- R2-D：分析 AO-04 的正式实验结果、训练阶段敏感性及可能机制。

R2/R2-D 没有发现静态 AO-04 可以稳定提高 selected AUC 的可靠证据。MovieLens 的改善接近零，KuaiRand 实验存在未完成运行与部分格子性能退化。

但这些结果不能直接否定 AO-04 的全部动态共享研究空间，更不能否定 Phase 2B 的其他候选。

此前的一个主要问题是：从文献候选中较早选择了 AO-04，之后持续围绕单一方向进行分析和实验，却没有充分比较其他候选在当前强基线上的真实研究潜力。

**现在要求重新开展一轮正式、全面、多方向的算法研究。**

本次研究不以节约计算资源为首要目标。目前拥有较充足的计算资源，允许多模型、多数据集、多随机种子、系统超参数研究、消融实验和机制干预。

最终目标不是再输出一份单纯依靠文献推理的方向排行榜，而是：

**通过充分的真实实验与深入机制分析，确定哪些研究问题成立、哪些算法能够可靠提高 AUC、为什么有效、能否超过简单替代方法，以及最终哪一到两个方向最值得形成顶会论文。**

### Stage F0：统一强基线复现与问题证据图谱

目标：建立可信的当前模型性能基准，确定哪些研究问题在合理的强基线条件下确实存在。

必须系统研究：

1. Sample-M3OE 在不同数据集的表现。
2. 与 MMoE、PLE/CGC 等成熟模型的公平比较。
3. 单域、单任务与联合训练的性能关系。
4. 域规模、标签分布、基础任务难度与 AUC 的关系。
5. 逐域逐任务的性能收益和退化。
6. 模型容量与参数预算对性能的影响。
7. 不同训练阶段的性能变化。
8. 共享专家、域专家、任务专家的实际利用情况。
9. 是否存在梯度冲突或更新级干扰。
10. 当前模型训练和推理的实际计算成本。

优先覆盖：

- KuaiRand。
- MovieLens。
- Ali-CCP（在核实数据接口、任务定义和协议可比性后纳入）。

必要时补充其他公开数据集，尤其是能体现真实多域、多任务特征且支持独立确认性评估的数据集。

模型容量、数据划分、训练目标、超参数搜索预算和验证集选模必须明确记录。

### Stage F1：跨研究方向的完整机制诊断

本阶段不是简单收集几个统计指标，而是针对各候选的关键科学假设，开展系统性机制实验。

主要研究任务：

**AO-01：逐格保护与优化空间**

检验 Sample-M3OE 是否存在稳定逐格退化；研究不同训练目标形成的性能权衡，以及是否存在可以改善受损格、同时保持整体性能的可行区域。

**AO-02：专家路由与容量利用**

研究不同域×任务的共享 gate 分布、专家利用、专家专化、输出相似性与实际性能之间的关系。

严格区分稠密 softmax 权重集中和稀疏路由的真实计算负载。

**AO-03：梯度与结构隔离**

系统研究梯度冲突、梯度方向、更新幅度、训练阶段、专家结构和逐格 AUC 之间的关系。

必须复核历史 S6–S8 的不利证据，不能重复已经失败的实验却忽略原结果。

**AO-05：容量分配与参数效率**

分析 M3OE 中实际参数预算、计算量和各专家族的容量利用情况，并通过控制实验研究结构与容量的关系。

**AO-04：选择性共享**

结合 R2/R2-D，区分静态权重、样本条件、训练阶段和结构选择的作用；不预设复杂动态模型能够改善性能。

**其余候选：**

分别建立符合 AO-06～AO-10 实际任务的机制诊断和比较协议，不得因为这些候选排名靠后而省略研究。

尽可能采用有判别力的干预实验，而不是仅凭代理指标与 AUC 的相关性推断机制。

例如：在相同模型状态下控制部分参数、路由或梯度操作，观察是否真正改变后续预测性能。

输出每个候选独立的机制诊断报告，以及综合证据表。

每个科学结论标记 STRONG / MEDIUM / WEAK / NOT IDENTIFIED。

### Stage F2：多方向正式算法设计与训练实验

本阶段允许同时开展多个独立算法研发分支。

每个分支必须依次完成：

1. 明确研究问题。
2. 明确当前已有方法为什么不足。
3. 定义可证伪的算法假设。
4. 设计核心算法操作。
5. 编写数学定义和执行规格。
6. 实现算法。
7. 独立代码审核。
8. 正式多种子训练。
9. 主要对照和消融。
10. 深入结果分析。

不能只因为新算法的 AUC 高于原始 M3OE，就认定算法贡献成立。

每个候选必须设置简单但有竞争力的替代方法，例如：

- 静态超参数调整。
- 简单损失或样本重加权。
- 参数量匹配的基础模型。
- 随机结构或固定门控。
- 标准已有优化算法。
- 只改变模型容量的对照。

对 AO-05，必须研究多个参数预算下的 AUC–成本曲线。

对 AO-01，必须研究逐格收益及整体性能的 Pareto 关系。

对 AO-02，必须分离目标负载分布与路由控制方式的贡献。

对 AO-03，必须区分梯度信息是否具有预测价值、以及条件触发是否真正改善训练。

对其他候选，也需要设计能够排除简单替代解释的正式对照。

算法的设计可以根据 F0/F1 的证据进行，但进入正式训练前必须冻结：

- 算法公式。
- 主比较对象。
- 数据与种子。
- 搜索空间和调参预算。
- 评价指标。
- 选模规则。
- 主要消融。
- 研究结论判定标准。

允许探索性算法迭代，但每次必须记录版本和修改理由，不能将探索性结果伪装成预注册确认性结果。

### Stage F3：泛化性、鲁棒性和机制干预验证

对 F2 中具有研究价值的候选执行完整验证。

至少考虑：

1. 跨数据集泛化。
2. 不同随机种子的重复性。
3. 不同域规模比例。
4. 不同域数与任务数。
5. 不同模型容量。
6. 不同训练阶段。
7. 不同优化目标。
8. 不同 backbone（适用时）。
9. 超参数敏感性。
10. 模块消融与竞争解释。

重点方法建议使用 6～10 个训练 seeds 进行进一步确认，数量可根据实际方差与计算成本调整，并记录调整依据。

对于改变域比例的实验，必须尽量控制域身份、任务身份、评价样本和数据划分，避免将规模因素与域内容混淆。

对机制性主张，优先实施明确的控制或干预，不得将相关性直接写成因果结论。

特别注意：KuaiRand 和 MovieLens 的历史测试集已经在多轮研究中被查看。后续正式研究必须明确区分探索性数据与真正独立的确认性评价。不得使用曾参与算法选择的测试结果证明新的独立泛化收益。

### Stage F4：跨方向研究综合与最终选择

独立分析全部候选的：

- 问题真实性。
- AUC 收益大小。
- 跨 seed 稳定性。
- 跨数据集普遍性。
- 逐格损益。
- 算法核心机制证据。
- 创新性与最接近工作。
- 简单替代方法是否足够。
- 参数、计算和工程成本。
- 继续深化可能产生的创新空间。

必须评价所有 AO-01～AO-10，不得仅讨论结果最好的方法。

对于不同任务的候选，不得强行混合不具可比性的 AUC 或成本指标。

由独立 Red Team 从论文审稿人的角度进行反向审查。

最终输出：

1. 研究问题是否成立的完整证据图谱。
2. 十个候选的最新证据与状态表。
3. 经实验修订的方向优先级。
4. 最值得作为论文主线的 1～2 个研究方向。
5. 对应的明确算法设计机会。
6. 距离一篇有竞争力的论文还缺少哪些关键实验。
7. 已经证伪或缺乏继续投入价值的方向。
8. 仍然不能回答的重要科学问题。

模型选择：GPT-6 Luna High

**Runner**

模型选择：GPT-6 Luna low

模型选择：GPT-6 Luna Extra High

**Independent Scientific Reviewer / Red Team**

## 六、正式科研纪律

1. **不预设阳性结果。** 允许方法失败，允许发现原有问题并不存在。
2. **不强行继承 AO-04。** 以最新证据独立评价其他候选。
3. **Sample 是强基线。** 不允许主要通过改善弱 Equal 目标来宣称获得新算法贡献。
4. **不混淆指标。** Macro AUC、训练份额加权逐格 AUC 与 pooled AUC 分别报告。
5. **保留原始结果。** 不覆盖旧报告、失败日志和无效运行记录。
6. **不忽略负面结果。** 必须分析与主要现象矛盾的 seeds、任务、域和数据集。
7. **不将 epoch 或单格当作独立训练重复。**
8. **不以固定 AUC 增幅代替统计分析。** 报告绝对提升、配对种子差值、不确定性及应用意义。
9. **不使用测试集选模、调参或决定追加算法实验。**
10. **不因计算资源充足而无控制地进行搜索。** 所有实验必须服务于明确的问题或竞争解释。
11. **算法优越性与机制正确性分别判断。** AUC 提升不自动证明预期机制成立。
12. **创新性与性能收益分别判断。** 复杂结构并不自动构成实质创新。
13. **训练失败不等于算法阴性。** 必须区分科学结果与基础设施异常。
14. **不允许通过事后修改指标定义、候选范围或评价规则制造正向结论。**
