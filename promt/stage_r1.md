# Stage R1–R3：MDMT 算法机会的自动化先导实验

## 一、角色与总体目标

你是 MDMT/M3OE 研究项目的实验执行主 Agent。

已完成：

- Phase 2B：算法研究机会识别。
- Stage R0：新候选与历史实验的证据核对。

本阶段要根据 R0 最终决策，使用现有 M3OE 代码、数据集与训练平台，完成代码审计、最小验证实验、多种子确认及最终实验分析。

最终目的不是证明某个候选方向有效，而是判断：

**现有强 Sample-M3OE baseline 是否存在可以被新的非平凡算法利用的 AUC 提升空间。**

允许获得阴性结论，不得为了得到正向结果不断调整实验。

## 二、Agent 分工

如支持多 Agent，采用：

**Main Controller**
- 控制实验阶段、预算与进入下一阶段的条件。
- 负责综合实验报告和最终研究决策。
- 不直接编写模型算法或运行训练。

**Experiment Designer**
- 将 R0 候选转换为可证伪假设。
- 制定实验臂、对照、评价指标和停止条件。
- 不执行实验。

**Coder**
- 最小改动实现算法对照。
- 保留可复现的配置文件和代码差异。
- 不擅自增加方法模块。

**Independent Reviewer**
- 独立检查代码与实验设计是否一致。
- 检查数据泄漏、训练目标、梯度路径、参数公平性和训练协议。
- 对错误要求修正并复核。

**Runner**
- 执行训练与评估。
- 完整记录日志、配置、结果和运行状态。
- 不负责解释论文价值。

**Experimental Analyst**
- 汇总指标，检查结果稳定性。
- 比较不同实验臂。
- 明确支持、削弱和否定的假设。

如果无法启动独立子 Agent，应按角色顺序执行，并以独立文档保留设计和审核记录。

## 三、Stage R1：代码与 baseline 审计

首先阅读 R0 输出和 M3OE 源代码。

确认：

1. M3OE 实际包含哪些共享、域和任务专家。
2. 各专家、门控和预测塔的参数数量。
3. 域专家融合中 β 和他域回收的实际定义。
4. 是否已经存在源域级或任务条件化的非均匀融合。
5. Sample objective 的实际代码实现与损失权重。
6. Equal/Sample 的定义是否与历史实验一致。
7. 训练/验证/测试集划分。
8. checkpoint 选择与 early stopping 规则。
9. 随机种子、模型配置和依赖版本。
10. 历史 baseline 是否可以严格复用。

不得根据论文的简化公式推测现有代码实现。

如果 R0 第一候选不是 AO-04，应根据其对应假设制定等价的最小实验，不得强行切换方向。

对于 AO-04，必须首先确定：

- 原始代码是否真的对所有他域专家等权回收。
- task gate 是否已经能够间接实现类似的区分。
- 改变融合权重时是否意外改变 β 的含义。
- 新增参数是否影响对照公平性。

输出：

- `R1_Architecture_Audit.md`
- `R1_Baseline_Protocol.md`
- `R1_Experiment_Charter.md`

Experiment Charter 必须预先定义实验假设、主指标、实验臂、可接受退化、运行预算和阶段停止条件。

审核完成前不得开展正式训练。

## 四、Stage R2：最小先导实验

如果 R0 推荐 AO-04，首先只检验最基本的性能机会：

### 假设

H0：原始 M3OE 的他域等权回收已经足够有效，引入非均匀源域权重不能产生稳定且具有实际意义的 AUC 改善。

H1：非均匀源域融合能够提供额外的、超出随机波动和简单容量差异的预测收益。

### 实验臂

B0：原始 Sample-M3OE，保留所有训练与选择规则。

B1：静态但可学习的非均匀他域融合。保留 β 总体控制，只学习其他域之间的相对贡献。初始配置必须与 B0 的前向输出等价。

必要时增加：

B2：更简单的非均匀权重基线，例如只按目标域学习、不额外引入任务维度。

B3：固定随机非均匀权重或与真实关系无关的权重控制，用于识别新增自由度和先验带来的影响。

不允许在本阶段直接实现在线亲和矩阵、复杂 EMA 估计器、动态选择性置零和多个附加正则项。

### 实现约束

- 保持原始 M3OE 主干不变。
- 保持 Sample objective 不变。
- 保持数据处理、batch size、优化器、学习率和早停设置一致。
- 新增权重必须归一化，且不得改变预定的总体他域融合质量。
- 不得删除原有计算路径。
- 初始权重等价性必须通过数值测试。
- 确认新参数能够获得梯度。
- 检查所有 domain-task 组合的输出维度。
- 新增参数与计算开销必须单独报告。

### 执行顺序

1. Reviewer 审核算法设计。
2. Coder 完成最小实现。
3. Reviewer 核对实现与设计。
4. 单种子、少量 batch smoke test。
5. 检查 forward 等价性、backward 和输出有效性。
6. 初步运行两个配对 seeds，判断是否存在值得进一步研究的信号。
7. 对异常结果排查实现与实验协议问题。

两个 seeds 只能用于初筛，不能用于宣称统计显著或确定方法有效。

主数据集优先复用已有训练配置成熟的 KuaiRand 或 R0 确定的更合适数据集。

不得根据测试集结果决定实验方向。

## 五、Stage R3：确认实验

仅当 R2 出现合理的正向信号、且没有证据表明收益来自实现错误或不公平比较时，进入 R3。

Seeds：
2022、2023、2024、2025。

优先使用：

- KuaiRand。
- MovieLens。

如需要更强的泛化检验，再考虑 Ali-CCP；不得仅因一个数据集阴性就无限制增加数据集寻找正向结果。

所有训练遵守既有项目协议：

- 最大 50 epochs。
- Early stopping patience=10，除非项目已有更严格且固定的规则。
- 验证集选模型。
- 测试集只评估预先确定的 checkpoint。
- 不允许选择各实验臂最有利的单个 seed。
- 基线与新方法使用相同调参预算。
- 所有结果按 paired seeds 比较。

如果历史 checkpoint 与代码版本、数据划分、目标权重、训练配置完全一致，可以复用；否则重新运行匹配 baseline。

### 评价指标

至少报告：

1. 各 domain-task 格子的验证集与测试集 AUC。
2. 各格 LogLoss。
3. 宏平均 AUC。
4. 采用明确权重规则的聚合 AUC。
5. 各格 AUC 相对 baseline 的变化。
6. 最差格、最大退化格和改善格数量。
7. 种子间均值、标准差及配对差异。
8. 参数量、训练时间和额外计算成本。

不得把逐格 AUC 的样本加权平均直接称为混合总体 AUC，除非明确其聚合定义。

AUC 变化约 0.003 可作为预先讨论的实用筛查参考，但不是通用显著性标准。应结合配对差异、任务重要性、方差和多重比较风险判断。

不得因为个别 seed 或单个格子得到微弱正向结果，就声称整体方法有效。

## 六、阶段性停止条件

以下情况应停止扩大实验，并记录结果：

- B1 与 B0 在固定协议下没有可重复的性能差异。
- B1 改善可以被简单 B2 或无意义的随机控制解释。
- 改善仅来自测试集选择或更多调参尝试。
- 个别格子改善伴随预先禁止的其他重要格子退化。
- 发现与原方法等价的现有算法已完整解决该问题。
- 新方法引入的成本明显大于已观察的收益，且不符合研究目标。

如果初步阴性结果基于过少 seeds，不得直接宣称理论不成立；可以依据预先规定的资源预算停止投入，并说明证据边界。

禁止因为结果不好而临时更换目标数据集、修改评价指标、延长训练或添加额外模块。

## 七、结果分析与研究判决

针对每个实验臂，依次分析：

1. 是否复现 baseline。
2. 改动是否产生了预期的机制变化。
3. AUC 是否出现稳定收益。
4. 收益是否具有实际意义。
5. 是否存在明显的负面影响。
6. 简单对照是否已经解释全部收益。
7. 是否有理由进一步开发新的亲和估计或共享算法。
8. 与最接近工作相比，剩余技术创新空间是什么。

最终结论只能是：

- GO：观察到可信的非平凡收益，值得进入算法开发。
- CONDITIONAL：存在信号但证据不足，需要明确的有限补充实验。
- STOP：没有足够收益或简单方法已经解决问题。
- INVALID：实验存在实现、数据或协议错误，结论不可用。

即使 GO，也不能直接宣称论文创新性成立；必须进一步进行最接近工作核验。

## Stage R1 额外约束：修正 R0 先导实验的因果解释

本阶段必须读取 R0 九份报告，但不得直接执行 `R0_Minimum_Pilot_Questions.md` 的原始阳性/阴性规则。

R0 的方向证据核对结论原则上保留；其 AO-04、AO-09 先导实验设计需要独立审核。

**AO-04 的核心目标是判断非均匀共享是否能够改善 AUC，而不是简单测量删除专家通道后性能是否下降。**

必须完成以下任务：

1. 核实当前 M3OE 实现的专家融合计算图、α/β 参数含义、任务维度和域维度。
2. 审查现有四种子 Sample-M3OE checkpoint 是否真实存在且能够复现此前的 baseline 结果。不可假定报告提及的 checkpoint 已经可用。
3. 区分置零消融、保持总权重的比例重分配、训练期可学习权重三种不同实验。
4. 对于 KuaiRand 三域设置，优先研究其他两个域专家的连续相对融合比例，而不是机械采用最低 20%/50%/100% 的删除比例。
5. 在推理期比例扫描中，保持总体他域融合权重不变，使用验证集选择配置，再于独立测试集评估。
6. 保留原始均匀融合和一个简单可学习非均匀融合对照；先验证简单权重是否足够，不直接实现完整在线亲和估计器。
7. 不允许将“删除某通道产生较大损失”直接解释为“均匀融合不是最优”。
8. 不允许将“删除通道影响很小”直接解释为“训练期非均匀融合无效”。
9. 严格区分描述性机制测量、冻结模型后处理收益和重新训练获得的算法收益。
10. AO-09 仅在有明确稀疏部署研究目标时执行，并检查是否产生实际计算收益，而不是只比较人为裁剪后的 AUC。
11. 提前固定主指标、实验臂、调参预算、验证集选择方式、测试集使用规则及停止条件。
12. 最终先提交经独立 Reviewer 审核的 Experiment Charter，再开始正式训练。

本阶段的成功标准不是确认 AO-04 有效，而是通过最小、可复现、公平的实验，判断其是否具有值得继续研究的非平凡 AUC 改善空间。
