The fresh attempt directory is `artifacts/heterogeneity_aware_20261115/attempt1`. Substitute the Python path above for `PYTHON` below; `REVIEW` is the review JSON path and `ATTEMPT` is the attempt directory. No command installs dependencies.

```bash

PYTHON -m experiments.heterogeneity_aware_20261115.run manifest --attempt ATTEMPT --review REVIEW
PYTHON -m experiments.heterogeneity_aware_20261115.run smoke --attempt ATTEMPT --review REVIEW --device cuda:0

PYTHON -m experiments.heterogeneity_aware_20261115.run tables --attempt ATTEMPT --review REVIEW
```

`pilot` completes all 60 full-budget trajectories and returns. It does not trigger HPO or read Test. The guardian keeps selected online/EMA weights and continuation states in RAM. `status --attempt ATTEMPT` reports raw epochs/job status. Scalar epoch and batch JSON/JSONL files are under `runs/<key>/attemptN/`; each completed job has `runs/<key>/result.json`.

Only when the orchestrator advances the predeclared continuation gate:

```bash
PYTHON -m experiments.heterogeneity_aware_20261115.run hpo --attempt ATTEMPT --review REVIEW --devices 0,1
PYTHON -m experiments.heterogeneity_aware_20261115.run select --attempt ATTEMPT --review REVIEW
PYTHON -m experiments.heterogeneity_aware_20261115.run confirm --attempt ATTEMPT --review REVIEW --devices 0,1 --configurations ATTEMPT/confirmation_configurations.json
```

`hpo` reuses the .03 pilot identities and runs at most two selected routes at .01/.05, both datasets and five seeds. `select` uses validation only and writes the candidate/control configuration list. `confirm` completes missing matching controls; it reuses source/config/data-identical complete trajectories. Same seeds are reused by user instruction, so this is not an untouched-seed confirmation. If A has positive five-seed incremental validation over B and C, the orchestrator may add `[dataset,"B_MATCH",alpha]` for both datasets to the confirmation configuration file and dispatch that one predeclared norm-matched contrast before freeze.

After all selected configurations/controls are frozen:

```bash
PYTHON -m experiments.heterogeneity_aware_20261115.run freeze --attempt ATTEMPT --review REVIEW --configurations ATTEMPT/confirmation_configurations.json
PYTHON -m experiments.heterogeneity_aware_20261115.run evaluate --attempt ATTEMPT --review REVIEW --devices 0,1
PYTHON -m experiments.heterogeneity_aware_20261115.run tables --attempt ATTEMPT --review REVIEW
```

`freeze` records selected hashes/epochs from the RAM guardian; `evaluate` reads Test only for those frozen selected states. Freeze blocks further scheduling. The table exporter writes selected and E10/E50 validation endpoints, selected Test endpoints when available, full six-cell/Macro/Traffic/Pooled metrics, five-seed summaries and paired seed/CI tables. No scientific interpretation is generated by runners.

After analysis/publication inputs are complete, `release --attempt ATTEMPT` releases RAM states and shuts down the guardian. The guardian JSON/socket metadata and data-only pickle cache are runtime files; do not publish them. No training state or checkpoint is written to disk. If a worker fails, inspect its `failure.json`; preserve its attempt. Retry the same job only after resolving its concrete cause, using the guardian's RAM epoch state. No batch-size reduction is automatic.
