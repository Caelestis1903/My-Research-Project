3. **Bugs/deviations found**

**R1 — CRITICAL: current integrity graph omits executable validator dependencies; ordinary-file check is bypassed by path resolution.** `V15_CONTROL_FILES` (lines 71–86) omits `stage_F0_postabnormal_v14.py` and `stage_F0_migration.py`, even though their executable validators are used by source/current validation. Neither is in runtime inventory. `EXPECTED_V14_SOURCE_SHA256` is unused. Their current hashes are respectively `5380ef1c3698f8b4ddfe34fce1bd8a4de15c04ad62f91a156bfcb273bb53298d` and `9e4c903277505a0e513f3e5f673ce3e263371722bf807a4a0cd7c4b2e4d103a0`. Changing these validators does not change either approved current inventory. Relevant launcher/migration/v1.4 regression tests and conftest are also omitted. `_repo_path` resolves the input before `is_symlink()` checks. An independently run isolated probe replaced an inventory source with an identical-target symlink: inventory validation accepted it unchanged. Bind the complete executable validation dependencies/current relevant tests and check original path kinds before resolving.

**R2 — MAJOR: first legitimate fresh completion blocks all further work.** `_validate_protected_snapshot_at_root` lines 820–835 gathers every `VALIDATION_COMPLETE` status, then requires the list equal frozen C97 and inventories all those IDs. With `allow_live_fresh_progress=True`, a newly completed F140 run therefore causes `v1.5 protected C97 status membership changed`. Restrict preservation comparison to frozen C97 and separately validate allowed monotonic F140 progress. The current E2E stops at CLAIMED, hiding this failure.

**R3 — CRITICAL: final transaction omits the locked live admission contract.** Final `commit_principal_release` lines 1498–1813 holds only execution-state lock; it never acquires worker/GPU locks in the required order, never checks current workers/slots/process count, and never re-queries assigned targets. It tests one caller-supplied observation once at lines 1603–1612, before lengthy inventory validation and before hold publication. No refresh occurs if >60 seconds elapse; no immediate pre-hold freshness/resource decision exists. Worker/slot evidence in audit is historical. Implement the specified locked live qualification and refresh at each decision; do not use fixture injection for production. Reentry after released hold also permits touched F140 via `allow_released_hold=True`, despite the required untouched/no-live-worker condition for nonterminal recovery.

**R4 — MAJOR: released hold and source preimages do not implement required evidence/history.** Lines 1762–1771 only replace active/release-ID/timestamp/source-hold fields. They never append `V15_PRINCIPAL_FRESH_ONLY_RELEASE` with incident/historical/set/target evidence, and overwrite the old `released_at_utc` without retaining historical timestamp metadata. PREPARED does not bind exact intended released-hold hash. The canonical current release pointer is absent from `_assert_frozen_artifacts`; lines 1627–1630 accept its arbitrary current digest/absence, and the archive loop only archives gate+hold, not release-pointer bytes. Freeze/check/archive the exact historical pointer and derive/bind the full specified released hold before PREPARED. Preserve every old event and old timestamp explicitly.

**R5 — MAJOR: fault boundaries do not establish durability before phase events on recovery.** If pending rename fault occurs before directory fsync, reentry sees expected bytes and skips `_atomic_replace_bytes`/fence, then appends `PENDING_GATE_DURABLE` (lines 1730–1743). The ledger directory differs from canonical gate parent, so ledger fsync does not fence that pending rename. Similar expected-state branches for pointer/hold lack explicit pre-event fences. Fault injection lacks separate file/parent fsync boundaries, preimage/archive publication boundaries and restart where final rename does not survive. Require exact file/parent durability fences before durable phase events, and separately exercise all specified syscall boundaries and restart alternatives.

**R6 — CRITICAL: incomplete/conflicting terminal graph is accepted; terminal ACK bypasses current source/review validation.** `validate_terminal_graph` lines 712–752 only requires first PREPARED, last COMMITTED, one COMMITTED and some hash agreements. It does not require all six ordered phases, same schema/transaction identity across rows, pending binding/internal release identities, or immutable authorized gate archive. Independent isolated probe supplied only PREPARED + COMMITTED with different transaction IDs; it returned terminal acknowledgement. `_transaction_rows` is not used by this admission oracle and itself permits skipped phases. The terminal ACK branch lines 1575–1600 calls only this weak oracle, not full current source/control/review graph validation, so drift after commit need not reject an ACK. Verify full exact ordered transaction and complete current graph under existing lock without querying or appending telemetry/logs.

**R7 — MAJOR: authenticated resource deferral accepts stale/inconsistent telemetry and lacks reviewed-target/phase identity proof.** `_validate_resource_deferral` lines 1167–1258 checks age of `decision_monotonic` but not observation-to-decision age.
