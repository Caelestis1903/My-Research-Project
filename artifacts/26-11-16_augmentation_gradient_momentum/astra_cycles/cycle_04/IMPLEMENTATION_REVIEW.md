Both a valid formal E1/step20 snapshot and an engineering ordinal1/step2 snapshot reproduced Immutable receipt differs at the canonical transactions/.../epoch_01.json. No real writes or IPC.

Tight correction: Preserve each uncommitted physical transaction with attempt identity; select exactly the successful ACK-bound transaction for the canonical scientific epoch. Reconcile a committed transaction without resending it. Permit a genuinely uncommitted epoch to create its next physical transaction. Do not overwrite/drop prior failed receipts or relax continuation/hash checks.

Focused acceptance: Finite failed-before-commit -> recovery -> new-attempt replay -> ACK case, plus the already-committed/lost-ACK case; all failed costs and transaction identities retained.
