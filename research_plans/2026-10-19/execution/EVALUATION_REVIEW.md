# Evaluation/readout implementation review

Primary self-review under start.md §11. No formal test metrics opened during implementation.

cm19_freeze.py requires every independent training receipt and full budget (or exact predefined long-step budget), original config, selection freeze, training-source hash agreement and written development disposition. It binds selected/final checkpoint SHA256, source and manifest before evaluation. This also prevents silent source or selected-state changes.

cm19_evaluate.py instantiates only the frozen model, loads selected/final state, performs torch.no_grad forward passes and each model's own neutral interventions, writes raw cell AUC/LogLoss/probability differences, instrumented forward timing and row-bound test predictions. There is no optimizer or update call. Checkpoint and source hashes must match the prior freeze. Source-style HAMUR normalization remains batch-sensitive; inference uses fixed physical batch40960 for baseline and neutral calls, and exact corresponding inputs. Test intervention is a sensitivity experiment, distinct from G2/G3 retraining.

cm19_collect.py uses seed as pairing unit. Six cells for joint models, three for single-task; weighted-cell metrics use original frozen training-population weights even for G4 subsets. Training-online AUC is explicitly not fixed-checkpoint training AUC. Selected/final columns stay separate. Descriptive95% t intervals use df3 and n4; no cell pseudoreplication and no multiplicity-adjusted confirmation. Matched private controls are present for joint task sharing; nominal and actual parameter counts differ for frozen serialized modules. Large raw diagnostic aggregates use lossless gzip rather than truncation.

Verdict PASS for readout code semantics. Ready for test runner: ONLY AFTER TEST_FREEZE.json exists and primary explicitly releases test stage after all formal training/development dispositions. This review does not authorize test use for model modification.

Offline mechanism/cost review: cm19_local_mechanism.py loads common diagnostic states and Adam m/v, recomputes a fixed train-meta evaluation-mode gradient and changes only modulation-group parameters for one hypothetical step. It reports preconditioner statistics, effective products and neutral functional contributions before/after, retaining all other weights. This is distinct from in-training gradient observations, and does not claim the preconditioner is a functional learning rate. Saved checkpoints and optimizer states remain unchanged. cm19_costs.py profiles supported dense forward/backward operations on a stratified train-meta batch and explicitly labels unsupported kernels/costs as excluded lower-bound coverage. Temporary gradients do not constitute a formal new training run; no test labels used. Both are raw diagnostics, not result interpretation. PASS for mechanical execution on completed runs.

G0 readout extension self-review: the optional `--stage G0` requires all160 G0 receipts, rejects test use and writes to a separate development_g0_readout directory. Default full-matrix collection and the test-freeze requirements remain intact. Training-online cell records are losslessly aggregated and retain their changing-weight interpretation. cm19_g0_readout.py joins model/fixed records on the same task, domain, optimizer, seed and checkpoint rule; it does not compare a single-task macro with a two-task macro. This is a descriptive unequal-capacity reference. cm19_offline_readout.py refuses collection until all48 local-state and78 cost tasks exist. No training implementation, optimizer update, manifest condition or selection rule changed. PASS for these readout-only extensions.
