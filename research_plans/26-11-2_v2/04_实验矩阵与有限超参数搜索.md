# 04｜实验矩阵、有限搜索与资源合同

## 1. 固定协议与科学重复

两个数据集、fixed1 骨干、原行序80/10/10、Sample 原BT预算、batch40960、FP32、50 epoch均按03。开发 seed2022/2024；本轮保留 seed2023/2025/2026。后者没有参与本轮选参，但历史研究使用过，不能称全新未知 seed。一个 `(split,dataset,seed,arm,有效配置)` 的完整 online 训练为一条唯一轨迹；online/EMA、任务、epoch、视图、重算都不增加统计 n。

所有性能门只使用指定 validation。先冻结阶段决定再执行下一阶段；原 test 和新窗口 confirmation split 在全部策略、选参、选点/模型 hash 冻结后统一打开。各模型 online/EMA 独立 earliest-best validation macro AUC 选点，另外保留共同 E50。E10 本轮不增加模型快照，只保留常规验证日志。

## 2. 队列与最大轨迹数

| 阶段 | 条件与训练臂 | 最大新轨迹 |
|---|---|---:|
| S0 | 来源/数据/实现/独立审查/CPU与真实CUDA Stage0；短测试不是科学重复 | 0 |
| S1 | ML、KR × seed2022/2024 × A0、A1、J0、J1、F0、F1 | 24 |
| S1R | F1在某数据集对A0有希望且未被F0支配，再跑该数据集FR两个开发seed | 4 |
| S2M（主分支） | 每数据集最多一个家族，仅一个κ减半点；J0/J1共4条，或F0/F1/FR共6条 | 12 |
| S3M（主分支） | 每数据集最多一个必要消融：J_SUM或F_PR，两个开发seed | 4 |
| S2B（备选分支） | 仅在主候选无可推进/可校准信号且未进入S2M/S3M时：TG/RG/AG×两数据×两开发seed | 12 |
| S4 | 每数据集最多一个获选机制，用三个保留seed；最多5臂配对 | 30 |
| S5 | 有希望者的额外划分窗口：每数据集最多3臂×seed2023/2025 | 12 |

**主分支上限：24+4+12+4+30+12=86。备选分支：24+4+12+30+12=82。** S2M/S3M 与 S2B 全局互斥；不能在主校准失败后再把备选叠上去。机器队列保存 `path_choice=main|backup|stop`，一旦开始任何互斥分支训练就不可改选。可以在一个数据集运行、另一个停止，实际数量相应减少。

86是无历史权重复用时的最大新增唯一轨迹，不是要求跑满。最少24条后全部停止合法。历史RAM状态已释放，不得假定旧权重可用；同一执行内严格匹配的完整轨迹可复用，必须扣减新增数并保留身份，不把相同重复算两次。

## 3. 阶段触发、选择与简单替代

S1顺序建议先A0/A1，随后J0/J1、F0/F1；所有正式臂均完成50epoch后判断，不能用EMA早期滞后提前淘汰。

S1R触发：F1相对A0固定EMA的开发均值≥.0005、2/2正，且保护未触发；同时F1相对F0均值>0。满足才派发FR，最多每数据集2条。无FR的F1不得宣称独立方向优势或进入F1确认。

主家族可直接推进：达到05的完整门；边界可校准：相对A0均值在[.0005,.001)、2/2正、保护为空，且相对已运行最强简单控制均值>0。J1用J0；F1必须先有F0/FR。强候选无需为“寻最优”强制多跑。

若至少一个数据集存在完整或边界主家族，选择 `main`；仅边界家族允许S2M。若所有数据集的J/F主方法及有希望的简单替代均无可推进/可校准信号，选择 `backup`，运行S2B；已经开始主分支后即使失败也不切换backup。两数据集都只有实质损害时仍可依合同运行备选，而不扩展方向。

每数据集S2M只选一个家族：先比较对A0的开发均值；差<.0005时选成本更低者，再平局选J。选择只用validation和实际测得成本；不得根据test或论文偏好选择。只增加κ/2：ML .025、KR .05，λ=.5及其他超参不动。J1与J0同调；F1/F0/FR同调，避免候选有搜索而简单控制没有。比较默认点和半κ点的两seed均值，保护不合格先剔除；近似平局<.0005选默认点，不无限折半。

S3M只对一个拟晋级主家族运行：J_SUM检查max-min；F_PR检查学生择向是否多余。两者是有决策价值的消融，不补齐全部开关排列。F1长期fallback>90%时仍执行F_PR；若F1无性能希望，直接停止，不为解释fallback另开训练。

获选规则：完整达门者中按EMA开发macro AUC最高者选；与更简单方法差<.0005时选简单方法，成本以Stage0/已运行ledger为准，再平局顺序J0→F0→RG→AG→J_SUM→F_PR→J1→F1→TG。简单方法只须对A0/A1通过实用收益和保护条件，不要求“新增复杂模块”门；结论限定为该简单增强的经验价值。

## 4. S4 确认配对，不遗漏基线预算

每数据集最多一个机制，冻结所有配置后运行seed2023/2025/2026：

- J1：A0、A1、J1，加开发validation中J0/J_SUM较强者R_J，共4×3=12条；差<.0005时选计算更便宜者，再平局选J0。J_SUM获选时配A0、A1、J0、J_SUM。
- F1：A0、A1、F0、F1，加开发validation中FR/F_PR较强者R_F，共5×3=15条；差<.0005时选计算更便宜者，再平局选F_PR。F_PR获选时配A0、A1、F0、FR、F_PR。FR使用冻结家族配置，在自己的当前状态构造F1反事实能量。
- TG：A0、A1、RG、AG、TG，5×3=15条。
- 若获选为J0/F0/AG/RG等简单替代：A0、A1、获选者，最多3×3=9条，不冒充复杂机制通过。

R_J/R_F在读取任何保留seed结果前冻结为具体方法，必须已经完成两开发seed，不允许未运行方法参与排序。没进入S4的其他控制只保留开发n=2证据，不冒充五seed机制确认；S4确认的是方法对强基线及最强必要替代的效用，而非所有组件归因都获得五seed支持。FR是计算不便宜的反事实匹配控制，不单独晋级为部署候选。

确认门失败即停止该候选，不改κ、rho、seed集合或选点。两个数据集可以选择不同方法，必须报告适用边界；不能事后把两种算法拼成一项跨数据集统一成功。

## 5. S5：预注册额外窗口

目的为判断当前选点/原行序区段特化，而非重新审计已停止的B2。规则现在固定：对原始CSV的全局原行号r及N，

```text
train_W1: 0 <= r < floor(.60*N)
select_W1: floor(.60*N) <= r < floor(.70*N)
confirm_W1: floor(.70*N) <= r < floor(.80*N)
```

KR先以上全局切分再筛tab0/1/4；只用train_W1重新fit encoder/scaler，OOV0。不得为了凑正例调整边界或改成按域分层。这个窗口位于旧train人口内，是**新的训练/选择/确认划分**，不是新的外部数据或此前从未使用过的样本，也不是已证实的时间外推。

只在S4的validation确认门通过时触发。使用已冻结配置、batch/epoch规则、原固定rho，不在新窗口重新调参。每数据集3臂：A0、获选者、其最强简单替代（开发validation在所有已运行简单对照中确定，平局选便宜者；若获选本身为简单方法，则第三臂A1）。seed2023/2025，最多6条/数据。新train步数与曝光不同如实记录，rho保持step时钟，不偷调成等epoch窗口。

在读取confirm_W1指标前冻结这些模型的select_W1选点与E50。所有六格须有正负例；若某格不具备AUC定义，记为窗口证据不足，报告人口/LL，不静默删格计算新的macro，不搜索另一个有利窗口。当前协议上的稳定现象可保留，跨窗口主张不得通过。

## 6. 成本：计算模型与实测分开

令F_B为全batch前向成本、G_B为全参数监督反向成本，F_S为目标子批前向，I_S为仅输入求导遍历，G_S为增强监督反向。源码的专家仍可能全部执行，精确耗时必须测量。

| 臂 | 每步主要计算，忽略纯代数小张量操作 |
|---|---|
| A0 | F_B+G_B |
| A1/J0 | F_B+G_B+F_S+G_S |
| J1/J_SUM | 上行再加F_S+2I_S |
| F0 | A1再加F_S+I_S |
| F1/FR | A1再加2F_S+3I_S（学生1次、教师2次输入遍历） |
| F_PR | A1再加F_S+2I_S |
| TG | A0+probe F_S+2I_S+2(F_S+G_S) |
| RG | A0+2(F_S+G_S) |
| AG | A0+probe F_S+2I_S+F_S+G_S；可复用相同视图 |

目标行比例ML约.195、KR约.0446。仅作预算估计，若G≈I≈2F且成本近似线性，A1/J0为`1+q`倍A0；J1为`1+8q/3`（ML约1.52、KR约1.12）；F0为`1+2q`（1.39/1.09）；F1为`1+11q/3`（1.71/1.16）。这些不是GPU实测倍率，不能写进结果表作为已测时间。稀疏gather、hook、SVD、日志、设备同步可能使估计失准。

每条轨迹正常每epoch验证online和EMA各一次，共100次完整validation forward；不是免费shadow。teacher仅目标子批，不能称无额外forward。所有臂保留两个selected和两个E50模型RAM快照；输入probe尽早释放。默认只有一个EMA参数副本；FP32参数本体约ML3.09MB/KR6.46MB（十进制），不等于峰值显存，Adam/激活/梯度/快照另计。

S0测单worker各家族真实step/epoch耗时、峰值CUDA内存、CPU RAM和验证成本。以实测估计剩余队列，并生成 `cost_forecast.json`；预算按实际触发臂计算，不先承诺整个86条耗时。记录train/probe/teacher/eval的forward行数、输入梯度遍历、参数backward、optimizer/EMA次数、GPU worker秒与队列墙钟，不能把遍历数直接称FLOPs倍数。

## 7. GPU 与 RAM-only 有限恢复

只用项目显式Python环境；核验GPU与外部作业，绝不终止或抢占既有任务。遵循现行显存/功耗85%调度门；若服务器规则更新，记录并执行更严格规则。先单worker校准，再按实测加并发。OOM只降低并发，不能改变batch、epoch、精度或数据协议。

模型/optimizer/EMA/RNG/loader状态**只留进程RAM**，不写checkpoint、临时模型文件、磁盘pickle或伪装日志的tensor。磁盘允许原始标量结果、hash、配置和资源ledger。短测试、失败、partial、恢复计算都计物理成本。

采用现有RAM IPC模式的最小修正：独立长寿命RAM guardian接收每epoch完整可恢复状态及selected/E50模型，确认接收后才标记 `RAM_COMMITTED`。worker失败时guardian尚存可恢复到上一epoch；协调器失败时worker/guardian只完成已冻结job，重连协调器根据ledger读取存活状态，不重新派发全部已完成轨迹。若guardian及worker内存均丢失，明确不可恢复，不虚构跨进程/跨机器checkpoint。

每个必要job最多一次原配置重试；第一次失败先定位或独占资源复测，不盲目连跑。已完成且标量记录齐全但权重丢失者，不全量重算；只对仍必须统一评价的晋级候选及配对基线允许一次重算，否则记 `EVAL_STATE_LOST`、结论限于validation。不能用已看过test替代缺失的独立比较。

全局物理成本上限为S0冻结的**当前获批派发队列预计成本×1.20**，预估仅在合法阶段新增job时相应增加，不能因失败无限上调单job估计。预计超限先取消尚未派发的校准、消融、非关键候选；已开始的必要配对优先完成。资源约束使必需控制缺失时记 `BUDGET_STOP_UNMATCHED`，不得当作通过；不放宽效用门。
