### HyperGate

Preserve all three official mechanisms: embedding/domain SENet gate, per-layer domain-conditioned additive expert biases, and task/domain-conditioned fusion gates over shared experts. Preserve domain/task augmentation MLPs, anchor embeddings, official detach placement, learned task anchors, auxiliary domain cross entropy and task BCE.

For non-domain embedding e, `a_d=A_d(sg(e))`, `a_t=A_t(sg(e))`. Domain control is `[a_d,sg(anchor_d)]`; task fusion control is `[a_t,sg(anchor_t),domain_control]`. SENet multiplies full embedding by `2 sigmoid(W2 ReLU(W1 domain_control))`. Each expert linear output receives the appropriate generated domain bias before its activation. Per-task softmax fusion combines experts and the task tower produces one logit. Auxiliary losses are domain CE(a_d·anchor_domain^T,d) and sum_t BCE(a_t·anchor_task_t,y_t), masked when labels are missing. Prediction never requires their labels; separate computation prevents the official score() label access from leaking into inference.

Official training target is **sum of per-task sample-mean BCE**, plus `lambda_d CE + lambda_t sum(task auxiliary BCE)`. Do not normalize the whole target to the M3OE scalar convention: relative auxiliary scale is algorithmic. Validation is always predictive six-cell macro LL, not total training objective.

HyperGate configuration must explicitly enable all three gates and `gate_input_type=augmented_embedding`. No fallback to all-False defaults. Proposed runnable research adaptation values are listed below; required fields can be supplied in an external explicit configuration, with strict validation and provenance.

### AutoIFS

Keep external official `AutoIFS.forward` and its four paths: scenario-shared→task-shared, scenario-specific→task-specific, scenario-shared→task-specific, scenario-specific→task-shared, including official bias algebra. LoRA A uses upstream Xavier-normal initialization; B starts zero. The selector receives detached backbone embedding during search; gate embeddings become a frozen copy at reuse. Search gates are sigmoid(temp·gate_logit). Final hard mask is **gate_logit > 0**, subtracted from the full task prediction as in upstream; positive mask therefore means removed path, not retained path.

Official search uses two disjoint Adam optimizers, non-gate lr and gate lr=0.01×lr; gate optimizer has no weight decay. Search objective is sum of the two task-mean BCE plus lambda1/lambda2 mean gate probabilities. Ten search epochs, temp=1 in epoch index0, multiplied by `100**(1/9)` before each subsequent epoch. Capture rewind **at start of zero-based search epoch9**, before that epoch's update. After epoch9 capture final selector network, final backbone embedding for gate embedding, and heads. Construct a new model from rewind backbone, then transplant final selector/gate embedding; set ticket=True, freeze all selector/gate-embedding parameters, and create a fresh non-gate Adam with reuse lr/l2. Preserve search→rewind→hard pruning→reuse; no skipped search or soft-gate final substitute.

Reuse maximum50 epochs; upstream stops on first failure to improve V macro AUC. The unified protocol changes the selection/stopping metric to V macro LogLoss, earliest tie within1e-12; retain first-non-improvement stopping (patience1). Search V curves are logged, but no search checkpoint is selected using E or Q. Remove upstream test evaluation after search and within train(); E is evaluated only through the final explicit evaluate command after freeze.

Exact supported upstream model topology is `[1024,512,256]`, yielding one scenario linear and one task linear to scalar; task_num=2. Do not generalize unsupported multi-task/multi-layer branches or fix unrelated base-class `pass` stubs. `use_bn=False`, dropout0 in formal configuration avoids unsupported singleton training BatchNorm behavior; rejecting unsupported bn settings is acceptable.

Model inference has no label parameter. `objective(x, labels, mask=None)` computes one forward pass and returns dictionary with scalar `loss` plus scalar named components; it must not execute two independent dropout forward passes for the same training step. Pipeline need not reimplement model-specific auxiliary scaling.
- HyperGate retains input-only domain/task augmentation outputs for its separate objective; labels enter only the task auxiliary BCE and primary prediction BCE, never the predictor's logits. With model.eval(), forward is deterministic and does not compute any label-dependent auxiliary loss.
- AutoIFS adapter exposes `.network` (corrected official instance), `.network.ticket`, `.network.temp`, and a method to export final selector (`gate_hypernet`,`gate_head0`,`gate_head1`,backbone embedding for gate embedding). Training owner can construct fresh adapter from same configuration, load rewind model state, load final selector into corresponding gate modules, set ticket/temp, and freeze gate modules using stable parameter names. The adapter's state dict must include all actual trained embedding/gate/core tensors; checkpoint metadata explicitly restores ticket/temp because upstream stores them as Python attributes. A wrapper state-dict extra-state is acceptable, not required if training checkpoint metadata restores them before inference.
- For non-AutoIFS methods pipeline creates one optimizer; for AutoIFS two during search, then fresh non-gate only during reuse. Stage logic belongs to training.py, core equations to model files. Model owner must supply named parameter grouping helper if wrapper prefixes change the upstream `gate` names; test disjointness/exhaustiveness by actual parameter identity.
- Formal config uses BN=False throughout new baselines, so B=1 is valid without changing training semantics. If an externally supplied BN=True configuration is supported, only BatchNorm layers for a singleton training forward may temporarily use their existing running statistics, then restore train mode, with a logged `SINGLETON_BN_RUNNING_STATS` event. Do not copy the sample, discard the tail batch, add fake data or change all dropout modules to eval. It is simpler and acceptable to reject BN=True as unsupported in this v1 configuration; no invented fallback is needed for the registered no-BN runs.
