The independent module `experiments/conditional_history_shared_update_20261122/final_evaluation.py` implements freeze, selected Test evaluation, and final scalar tables for the 2026-11-22 plan. Its synthetic checks are in `tests/test_final_evaluation.py` in that package. The existing training CLI and its active A/B source closures were not edited.

## Inputs and selection authority

The design input is `DESIGN_SPECIFICATION.md` in this report directory. Plan inputs are 00, 05, 07, 09, 10 and 12 under `research_plans/26-11-22_conditional_history_shared_update`. Runtime inputs are the local artifact root, its S0 data identities and reuse manifest, both accepted core checks/audits/reviews/run receipts, all required completed job/guardian receipts, A stage decisions and endpoint tables, B gate/LOSO records, 40 accepted anchors and 20 parent windows, and each triggered dataset's 20 pulse slots. The registered A decision chain determines which A conditional stages are mandatory. B gates determine pulse/search requirements. The completed S4 search requires all 60 distinct accepted jobs across both datasets and both eta values. Each completed AB/G stage requires the two datasets and all five seeds. Triggered stages with missing evidence block freeze. The closure retains the reasons and hashed evidence for skipped branches.

The foreground orchestrator materializes its Validation-only scientific selection at `artifacts/conditional_history_shared_update_20261122/S5_SELECTION.json`. This is a scalar handoff from the completed S2–S4 decisions. Its fields are listed below.

- `author`, `artifacts_root` (absolute), `split="validation"`, `test_used_for_selection=false`, `status="NO_CANDIDATE"` or `"FINAL_CANDIDATE"`.
- `core_gate_sha256` maps A_CORE to its decisions.json SHA256 and each dataset name to its final B_GATE file SHA256, including the pulse decision when applicable.
- `branches` has exactly A_HISTORY, A_DOSE, A_SCOPE, B_SEARCH, AB_FROZEN, G_FROZEN. Each entry has `status="COMPLETE"` or `"NOT_TRIGGERED"`, a reason, and `evidence` mapping real file paths to their SHA256 hashes. Include the scientific inputs for bridge/Gaussian decisions and any replay or localization required by the stage. Completed A stages also carry their `decision_sha256`. Completed B_SEARCH/AB/G stages carry `results`, the complete list of accepted result.json paths. An active, deferred, incomplete or technically paused branch cannot close as a scientific negative.
- Runbook 00 permits a triggered Gaussian supplement to pause on a control identity mismatch. In this case G_FROZEN takes `TECHNICAL_BLOCKED` with its reason and an empty or omitted `results` list. Its evidence must bind the absolute paths and SHA-256 hashes of `SOURCE_G_CONTROL_AUDIT.json` in the artifact directory and `G_CONTROL_REVIEW_RECEIPT.json` in the report directory. The audit records stage G_FROZEN, status TECHNICAL_BLOCKED, reason, author, trigger_sha256, and exact_control_seeds for both datasets. The independent receipt records stage G_CONTROL, verdict PASS or PASS WITH FIXES, empty blocking_issues, reviewer, and audit_sha256. S5 checks the missing seed coverage, independent reviewer, and the original Validation trigger. Only its unaugmented A candidate can enter the candidate matrix. An existing TRIGGERED Gaussian receipt rules out a NOT_TRIGGERED handoff.
- NO_CANDIDATE carries a reason and no dataset selections. After the validated closure, report records zero new Test evaluations and preserves all already-exposed historical core selected Test rows in a distinct context table. The A/B Validation/mechanism results remain tied to the source files in the closure. The evaluate action rejects this status.
- FINAL_CANDIDATE carries `datasets` keyed by movielens and kuairand. Each entry has `candidate`, `parameters` as the resolved candidate job's method-specific config keys and values, `strongest_published` (M3OE_FIXED1_ADAPTED / HYPERGATE), and `strong_internal` (A00 or G-D0 on the augmented background). Local conditional required controls use `result_paths[arm][seed-as-string]` pointing to each accepted result.json. The core selection, archive and core job paths are derived. Historical baseline IDs are M3OE_FIXED1_ADAPTED, HYPERGATE, AUTOIFS. Their native selected online readout is compared to the selected fixed EMA of internal methods.
- For A, include `parameters.lambda_pair`, `matched_adam` (A10 at .05 or A41_ADAM_L025 at .025), and `history_form` for reduced-dose/restricted methods. Restricted methods also require `scope` and `full_history`. For B include `parameters.eta`; ADAPT/STATIC/UNIFORM use the same registered comparison eta. AB includes `a_single`, `b_single`, `stronger_single`, and the corresponding constituent parameters/controls. G includes `unaugmented` and the constituent fields for that method. The freeze requires a common form and scope, binds the complete accepted training config in each new endpoint, compares the declared candidate parameters with the job config, and checks positive Validation increments on an eligible target. The independent selection reviewer verifies the scientific choice, factorial constituent/config match and all conditional decisions from the bound S4 evidence.

The independent code reviewer writes `S5_REVIEW_RECEIPT.json` in this report directory after review. Fields are stage S5, verdict PASS or PASS WITH FIXES, empty blocking_issues, design_sha256, report_sha256 (this report) and files mapping all module-relative names from FINAL_FILES to their SHA256 hashes. After the scientific selection, its distinct reviewer writes `S5_SELECTION_REVIEW.json` with stage S5_SELECTION, accepted verdict, empty blocking_issues, reviewer identity, selection_sha256 and code_review_sha256. The implementation does not create either approval. Source files and the numerical v3 manifest are verified on every production action.

## Freeze and evaluation

The result adapter expects the existing runner layout `<attempt>/runs/<job-key>/result.json`, sibling COMPLETE_VERIFIED.json, and owner-generation attempt directories containing epoch and RAM scalar receipts. It verifies the job, config, group, population, source, full 50-epoch Validation curve, earliest strict maximum and matched loss. It directly reads the selected state from the current guardian and verifies generation, final transaction, job, attempt, selected epoch, Validation scores and tensor hash. The active guardian's completed packet retains only selected_models, selected_epochs and selected_validation. Its separate live job registry and accepted result carry the final transaction, configuration and attempt identity. The synthetic guardian check uses this compacted shape. Any later S4 runner that changes this layout must provide a separately reviewed matching adapter before using its states.

Historical selected endpoints are read from fixed Git blobs. The two core tables use `875215c1e509ab55c1b6632d4f5d13e8b94782da` and `a06f9d3e544a8658b2d24ddc8f7d10d3f20f0288`. Published and Gaussian references use `c8675ae2923c15b6965884b140b5b646690cd95e`. The overnight endpoint table and Gaussian ML audit/KR manifest bind original AUC selection and the population. Raw/array/row hashes and preprocessing identities must match current S0. Historical Test rows must match the frozen Validation selection, trajectory, model, config, readout, epoch, and source identity. No new published control is trained.

FINAL_FREEZE.json is an immutable, content-addressed scalar packet with the selection, comparisons, controls, parameters, per-seed identities, source evidence and script identities. Each pending new state gets a fresh readback before evaluation and a second verified load immediately before its Test pass. Each unique physical state is scored once, including when it occupies several roles. Scores and measured costs share a durable scalar receipt. Archive reuse costs zero new forwards. A process lock serializes evaluation. A crash before the scoring intent is retryable. A crash after intent without a durable result leaves an indeterminate slot closed to automatic re-scoring; recover its scalar receipt or report the technical blocker. A restart consumes completed receipts. No model/optimizer tensors are written to disk.

Under the original 11-22 runbook, the completed reviewed matrix, eligible frozen selection and current selected identities authorize final evaluation for this study. An explicit stop during execution ends work at an atomic boundary.
