## Training and retained states

The zero-dose factory returns source A0. Ordinary Adam retains its single .9 mixed first moment on all parameters. A40 uses the same two-channel optimizer and diagnostic shadows as A21.

The dedicated A40 process calls history_runner.worker directly. The held states at E5/E20/E35/E50 use the A_HISTORY RAM schema and key format. Each packet has the post-forward/pre-step model, optimizer and EMA, the full RNG/loader state, permutation, cursor, row IDs, pair indices, raw pair and mixed gradients, live moments, per-source .9 and .99 shadows, prior selections, pre-forward buffers/RNG, and actual post-step hashes. A41 uses runner.worker with its endpoint formatter temporarily bound to the accepted history science formatter in the single worker process. This ensures that A41's physical and endpoint cost roles both identify new training.

The pair generator hashes dataset, seed, epoch and global step plus the condition or pair_indices stream. It excludes dose and arm. Each draw's ordered sampled physical row IDs have a SHA256 in the per-batch diagnostic log. Datasets and original split/population identifiers are tied to the prior audited data. Both online and fixed EMA retain E10/E50 and their own earliest strict Validation maximum over E1–E50.

## Stage entry points and scientific gate

Use the project Python executable with module experiments.conditional_history_shared_update_20261122.dose_stage. The actions are audit, check --gpu N, run and analyze. Audit verifies the prior gate, its scalar evidence, reviewed history runtime and live RAM generation. Run and every child worker require A_DOSE_REVIEW_RECEIPT.json in this report directory. The reviewer supplies stage, verdict, empty blocking_issues, source_hash, design_sha256 and check_sha256. The worker validates its direct supervisor PID. The foreground scheduler uses live per-device memory and power, live host RAM and the measured physical-capacity rule, then resamples after startup. It pauses on an unexpected exit or an incomplete worker.

Plain analyze produces the endpoint, paired-seed, paired-summary and provisional decision tables under tables/A_DOSE_PRELIM. The final analyze --localization reads tables/A_TARGET/localization.json, requires the matching localization_sha256 in the COMPLETE A_TARGET_RUN.json, and writes the official tables/A_DOSE decision. Both paths use reviewed results.write_stage with verified A00, A10, A21, A40 and A41 Validation inputs and the frozen target.

## Engineering verification

The check compares two natural batches per dataset and arm against the original optimizer and objective using the same reduced coefficient. It checks model, EMA, ordinary optimizer, moments, history tables, selection/clock state, loss and pair identities. Both arms must draw the same rows and pairs as each other and the paired-row hashes must agree with the reviewed high-dose fixture. A40's saved tail is read back from the guardian, applied on a clone, and compared with the actual model, EMA and complete optimizer hashes. Fixture anchor keys are released after comparison. These checks create no scientific trajectory and evaluate no Validation or Test metrics.
